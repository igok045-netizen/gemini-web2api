# Gemini Web2API

Локальный сервер с веб-админкой, который предоставляет OpenAI-совместимый API для веб-версии Gemini. Его можно подключить к OpenCode и другим совместимым клиентам. Проект основан на [zexadev/gemini-web2api-go](https://github.com/zexadev/gemini-web2api-go); лицензия оригинала сохранена в [LICENSE](LICENSE).

Это неофициальная интеграция с веб-интерфейсом, а не официальный API Google. Доступность моделей зависит от аккаунта и лимитов; Google может изменить веб-протокол или отклонить запрос. Ответы иногда приходят с большой задержкой.

## Быстрый запуск на Windows

1. В разделе **Releases** скачайте `gemini-web2api-windows-amd64.zip` и распакуйте в отдельную папку.
2. Запустите `Start-Gemini.cmd`. Сервер работает в фоне, админка откроется по адресу [http://127.0.0.1:8084/admin/](http://127.0.0.1:8084/admin/).
3. Войдите в Gemini в Firefox. В админке откройте **Cookie Pool → Import Cookie** и добавьте cookies этого аккаунта. Для получения строки в Firefox откройте инструменты разработчика → **Network**, обновите страницу Gemini, выберите запрос к `gemini.google.com` и скопируйте значение заголовка **Cookie** из раздела заголовков запроса. Нужны как минимум `SAPISID` и `__Secure-1PSID`.
4. Нажмите **Check** в Cookie Pool. После первоначального импорта сервер может автоматически брать актуальную сессию из стандартного профиля Firefox, сверяя её с сохранённым аккаунтом. Если профиль не найден автоматически, укажите полный путь к его `cookies.sqlite` в переменной окружения `GEMINI_WEBCHANNEL_FIREFOX_COOKIES_DB` и заново запустите сервер.
5. В админке откройте **Settings** и скопируйте локальный API key для настройки клиента. Не публикуйте этот ключ, cookies, базу данных или HAR файлы.

Если в Firefox вход выполнен заново и идентификаторы сессии изменились, проверка сообщит о несовпадении. Отключите старую запись и импортируйте текущие cookies. Нет необходимости обновлять их по расписанию. Смена VPN или сообщение о лимите модели сами по себе не означают, что cookies устарели.

Архив предназначен для Windows x64. Запускной скрипт включает экспериментальный бинарный WebChannel, прямой HTTP/3, чтение cookies Firefox и строгую проверку сообщённой модели. Если Firefox недоступен, сервер запустится без автоматического чтения его профиля; тогда используется импортированная запись cookies. HTTP/3 не поддерживает прокси, заданный внутри программы. Системный VPN работает на уровне сети. Бинарный режим и резервный путь изображений экспериментальные; их работа может отличаться в разных системах и аккаунтах.

В релизе также доступен отдельный исполняемый файл для ручного запуска. Без файлов из архива он использует обычные настройки сервера, порт 8083 и не включает автоматически чтение профиля Firefox. Для описанного выше запуска используйте архив.

## Подключение OpenCode

Добавьте провайдера в конфигурацию OpenCode 2 и подставьте **свой** локальный ключ вместо заполнителя:

```json
{
  "providers": {
    "gemini-local": {
      "name": "Gemini local",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://127.0.0.1:8084/v1",
        "apiKey": "YOUR_LOCAL_API_KEY"
      },
      "models": {
        "gemini-3.5-flash-lite": { "name": "Gemini Flash Lite" },
        "gemini-4-argon": { "name": "Gemini 4 Argon" }
      }
    }
  }
}
```

Модель Argon появляется при наличии подходящего аккаунта; доступ и её название зависят от текущей реализации Google. Проверить список можно через `GET /v1/models` с локальным API key. В случае `gemini_model_downgraded` сервер сообщает о несовпадении модели, а не выдаёт Flash Lite за Argon. При `gemini_outcome_unknown` запрос мог быть получен Google, но его результат неизвестен. В каталоге [internal/app/opencode-gemini-retry-guard](internal/app/opencode-gemini-retry-guard) находится необязательный плагин, предотвращающий автоматический повтор таких запросов в OpenCode 2.

## Исходники и сборка

Нужен Go версии, указанной в `go.mod`:

```powershell
go test ./...
go build -o gemini-web2api.exe .
```

Для ручного запуска используйте `config.example.json` как основу и задайте параметры через конфигурационный файл или флаги. Приложение хранит локальное состояние и данные аккаунта в базе SQLite. Не добавляйте рабочую базу, куки, журналы или экспорт браузера в Git.

В составе проекта — Go сервер, встроенная веб-админка и тесты. Проверены короткие запросы, потоковые ответы, отдельные изображения и вызов инструмента OpenCode. Не обещается отсутствие тайм-аутов, поддержка всех моделей или точное совпадение сетевого поведения с браузером. Длинный контекст в бинарном WebChannel ограничен; при превышении сервер возвращает `context_length_exceeded`, чтобы клиент мог попытаться сжать историю.
